# UI Context

## Design Tokens

Official palette, extracted from the logo, defined as CSS vars (`frontend/src/
index.css` and the landing-specific `--l-*` tokens):

| Token | Hex | Use |
|---|---|---|
| Primary blue | `#3248CE` | Primary actions, brand |
| Secondary blue | `#2B79E8` | Accents, links |
| Teal | `#1BC9A8` | Success, positive states |
| Night | `#080B1C` | Dark backgrounds (landing, auth) |

No component hardcodes a hex value or an inline color outside these tokens. A new
color need is a new CSS var, not a one-off hex in a component.

## Component Conventions

- Tailwind classes + isolated sub-components for new UI. No `createElement`-style
  CSS injection.
- Dashboard/veille-style screens use inline `style={{ ... }}` with `var(--l-*)`
  tokens -- this is the real, established convention in those files specifically
  (not an exception to fix), match it there rather than introducing Tailwind
  classes into an inline-style file or vice versa.
- Every API call goes through `frontend/src/api.ts`. A component never calls
  `fetch()` directly.
- All copy through i18n (`frontend/src/locales/fr.json`/`en.json`), never a
  hardcoded string in a component.

## Rejected Patterns

Review blockers, confirmed repeatedly during this project's landing/auth page
work -- these read as AI-generated by default, avoid them without being asked
each time:

- Pill / `rounded-full` buttons. Use `rounded-xl`/`rounded-2xl`.
- Eyebrow/kicker labels above headings.
- Generic glow badges, gradient-button-by-default.
- Feature grids with icon-in-circle as the default treatment.
- Alternating section background colors as a layout crutch.
- GSAP ScrollTrigger pin+scrub for scroll animation. Use the project's own
  `useScrollReveal()` hook (`IntersectionObserver`-based `.animate-on-scroll`/
  `.is-visible` classes) instead.

## Responsiveness

Mobile-first. Check a component at a small mobile width before tablet and desktop,
not a desktop layout adapted down afterward. `useIsMobile()` is the established
hook for conditional mobile behavior (see `VeilleFilters`/`AoDetailPanel`'s
overlay-on-mobile pattern).

## Navigation

Real `<a href>`/`<Link>` for primary navigation (crawlability, browser history
semantics), not `<button onClick={navigate}>` for anything that is conceptually a
link. Back-button behavior uses `navigate(-1)` (real browser history), not a
hardcoded push-to-home.
